# UI_SPEC — Captura y seguimiento epidemiológico offline
Versión 0.1.0 | Estado: especificación candidata | Base app/app.py, contrato v2. Fuentes: MVP_SPEC.md, DATA_CONTRACT.md, capture_schema.json, NLP_SPEC.md, TERRITORIAL_SPEC.md.

## 1. Decisión de integración
Mantener las tres pestañas existentes (Triaje prelaboratorio, Auditoría preanalítica, Vigilancia poblacional) para no romper navegación y pruebas. Añadir navegación principal en barra lateral: Captura y registros (predeterminado), Análisis clínico (contiene las tres pestañas existentes), Territorio y brigadas, Exportación. Esta es decisión propuesta; actualizar tests/test_app.py solo en navegación justificada, conservar comprobaciones de seguridad. `app/app.py` único punto de integración; nuevos `app/capture.py`, `app/storage.py`, `app/nlp_engine.py`, `app/speech_to_text.py`, `app/territorial.py`, `app/exporter.py`. No modificar src/config/models. Captura debe iniciar aun si falta cohorte o falla carga del motor; no usar st.stop() global por fallo ML. No exponer servidor a red pública; mostrar 'Ejecución local' y no afirmar estado real de Internet solo por etiqueta.

## 2. Pantallas y comportamiento
| Pantalla | Componentes | Acciones y estados |
|---|---|---|
| Captura y registros | Nueva ficha, listado local, búsqueda por ID local, estado y fecha, selección de versión | Crear UUID, abrir borrador, recuperar tras reinicio, crear versión al editar, aviso si cambio sin guardar |
| Editor de ficha | Secciones por `section` de capture_schema; 82 campos originales + 20 operativos según aplicabilidad; campos de laboratorio en panel separado | Guardar borrador, revisar, validar, finalizar, evaluar; errores por campo, no pérdida de datos |
| Asistente dentro del editor | Texto, grabación opcional, transcripción editable, tabla de propuestas con evidencia | Extraer, aceptar/rechazar individualmente, revisar conflictos, aplicar patch versionado; nunca autoevaluar |
| Análisis clínico | Triaje M1+SHAP, fenotipo M3A, auditoría M3B, vigilancia sintética | Usar caso/version seleccionado; conservar modo demo separado; mostrar artefacto y aviso experimental |
| Territorio | Selección de alcance y datos ficticios, parámetros, puntos, demanda, rutas | Ejecutar DBSCAN, optimizar, mostrar aislados y demanda sin asignar |

## 3. Editor de ficha
Secciones generadas del esquema: notificación, paciente, exposición, dieta, clínica, laboratorio y cierre según etiquetas exactas del JSON. No reprogramar los 82 identificadores a mano. Cada campo tiene un widget propietario único; gingivitis y temblor distal no se duplican. Los siete indicadores de vía/tipo son controles auxiliares de campos agrupados y no 7 nuevos ítems oficiales. Usar campo agrupado y representación individual consistente; en evaluación parcial enviar indicadores explícitos y omitir fallback agrupado. Renderizar 'Otro' como texto original complementario sin crear predictor. No inventar catálogos oficiales; valores categóricos entrenados desde transformadores verificados si disponibles, más valor original fuera de vocabulario con advertencia. Si no carga ML, permitir texto original y guardar.

Tipos: binarios selector sin dato/Sí/No más estado semántico; ningún valor inicial No. Numéricos nullable (st.number_input value=None), unidades visibles, límites backend como advertencia si el dato original está fuera de dominio. Texto de CI/teléfono sin coerción numérica. Fecha exposición permite AAAA-MM; no completar día. Datos infantiles, duración original y unidad en metadatos; conversiones pendientes no se ejecutan. Campos no aplicables conservan motivo; ocultar condicionalmente no elimina valor previo. Dictamen y validaciones de laboratorio son acciones profesionales explícitas. Las condiciones de aplicabilidad reproductiva no deben inferirse exclusivamente por sexo o edad. Finalizar requiere fecha de notificación según regla operativa propuesta, no CI/teléfono. Borrador permite incompletitud.

## 4. Estado Streamlit y persistencia
Estado de sesión limitado a caso activo, versión esperada, buffer de edición, propuestas y resultados visuales; SQLite fuente persistente. Claves de widget `capture:{case_id}:{field_id}` (añadir versión/epoch de recarga controlada), no reutilizar claves entre casos/demo. No escribir estado de widget después de instanciarlo en el mismo rerun: aplicar patch mediante callback previo o recarga explícita de buffer y rerun. Evitar st.form único que impida acciones NLP intermedias; dividir secciones o usar controles fuera del form y botones explícitos. Al cambiar caso limpiar transcripción/propuestas/resultados anteriores. No usar cache_data global para casos ni audio. Cache_resource solo artefactos de confianza y modelo Vosk. Guardar transacción identidad + versión + PII + auditoría, con control optimista; conflicto recarga o nueva edición, nunca sobrescritura silenciosa. No guardar en cada rerun; botón explícito y estado guardado visible. Si falla disco/DB informar y mantener buffer para recuperación, no afirmar guardado.

Estados de registro persistente: draft/validated/archived (DATA_CONTRACT). Pendiente revisión NLP, evaluado, exportado son eventos/estados de interfaz derivados, no sustituyen record_status. Flujo: nueva ficha -> edición -> revisión de propuestas -> validación -> guardar versión -> evaluación opcional -> nueva versión con laboratorio. Evaluación y exportación no modifican versión previa. Si motor falla, guardar disponible; mostrar error técnico resumido sin PII y botón reintentar. El caso Probable requiere aviso de notificación inmediata conforme guía p.38, no afirmar envío. Confirmado depende de regla existente y revisión profesional. No presentar alertas sintéticas como diagnóstico ni negar atención por score bajo.

## 5. Interacción NLP
Asistente fuera del formulario que contiene los widgets de datos. Entrada textual manual siempre disponible. Transcripción no se aplica automáticamente. Tabla con concepto, valor propuesto, fragmento, contexto, dato actual, decisión; por defecto pendiente. No aceptar históricos/terceros/ambiguos directamente; permitir edición manual independiente. Al aplicar, comprobar versión y conflictos; actualizar solo campos aprobados y su procedencia. Mostrar cuántos se aplicaron/rechazaron y cuáles requieren revisión. El dato no mencionado no cambia. Audio no persistente, texto sensible restringido. El conjunto permitido es exactamente el de capture_schema (34 campos); factores laborales no autorizados aún quedan manuales, no anunciar cobertura que no existe.

## 6. Laboratorio e inferencia
Mostrar matriz, unidad original, valor nullable, fecha toma/envío, segmento si aplica y validación profesional. Distinguir orina ug/g de ug/g Cr. Varias mediciones: seleccionar panel explícito, no resolver por última fila arbitraria. `validate_record()` y adaptador positivo antes de predict_patient(); conservar errores originales. M1 se muestra desde instantánea prelab versionada; M3B solo si elegible; no sobrescribir M1 tras laboratorio. Explicaciones SHAP del modelo independiente en log-odds, no causalidad. Mostrar falta de evaluación en vez de cero. Mantener avisos de cohorte sintética y métricas congeladas separados de casos locales.

## 7. Diseño y operación offline
Interfaz española, contraste suficiente, etiquetas completas, teclado, foco visible, mensajes con texto además de color, disposición adaptable a portátil; no depender de fuentes, imágenes, mapas o scripts CDN. Gráficos locales Plotly. Sin telemetría, sin API remota; localhost 127.0.0.1. Probar micrófono en navegador local; si permiso denegado mantener texto. Solo pacientes ficticios. No mostrar PII en listados, logs, métricas, exportación analítica ni capturas de pantalla. No autenticar ficticiamente: SQLite sin cifrado y sin control de acceso no es apto para datos reales.

## 8. Criterios de aceptación UI (AppTest + prueba manual)
U01 iniciar sin Internet y sin cohorte; captura disponible. U02 82 IDs únicos y todos representados, incluyendo derivados documentados y 20 operativos. U03 0/null/no aplica sobreviven a guardado/reinicio. U04 guardar borrador incompleto; finalizar con errores muestra campos. U05 cambiar caso limpia estado y no mezcla pacientes. U06 NLP negado se aplica solo tras aceptación y no cambia otros campos. U07 conflicto de versiones no pierde ediciones. U08 fallo de modelo no impide guardar. U09 M1/M3A funcionan con artefactos íntegros; M3B no puntúa sin laboratorio. U10 resultado urinario en unidad incompatible se rechaza; cero medido se conserva. U11 exportación sin PII. U12 territorio muestra aislados y faltantes. U13 no hay solicitudes externas durante operación desconectada. U14 regresión de tres pestañas y escenarios existentes preservada o cambios justificados. U15 fallo voz mantiene texto/manual. U16 aviso probable y limitación clínica visibles. No marcar aprobada una prueba no ejecutada.
